## 1. 何を判定するか

AI-GEN4単独と、AI-GEN4にJevの探索順序提案を加えたAIを実際に対局させ、勝敗で比較する。Jevの回答を待つ時間、入力準備、応答検証、費用・応答記録は探索時間から外す。両者にそれぞれ2秒の探索時間を与え、「通信待ちを許した場合、この組込み方式によって棋力が改善するか」を調べる。

Jev単体の棋力やJev一般の能力を測る試験ではない。両者の総所要時間が同じという条件でもない。最大深度に達して同じ手を選ぶ場合も結果に含める。深度、ノード数、Jevのconfidenceを勝敗の代わりに使わない。

既存の予備対局・64局面再生比較は、通信待ちを含む別条件の参考記録として保持する。新試験へ成績を合算しない。Jevの正式採用、公開AIへの組込み、AI世代更新、本番配信は結果にかかわらず行わない。

## 3. 時計を開始する位置

Jev側の処理順は以下とする。

1. 保存局面・合法手を確認し、要求を準備する。
2. API要求を予約・送信し、最大60秒待つ。
3. モデル・候補・確率などを検証し、使用量と有効応答を保存する。
4. **ここで探索用の2秒時計を開始し、共通のanalyze関数を呼ぶ。**
5. 合法な着手を確定し、棋譜を保存する。

基準側も、実行環境などの準備を終えてから同じanalyze関数の直前で2秒時計を開始する。探索内部の局面遷移、評価、順序付けなどは両側とも探索時間に含める。候補側のAPI待ち、入力準備・検証・保存を探索枠から差し引かない。例えば回答に10秒かかっても、その後に2秒探索する。

API待ち時間、探索前処理時間、探索実測時間、1手全体の時間は分けて保存する。同期処理の単位で期限を超える可能性があるため超過も保存する。探索枠の超過が50msを超えた場合は棋譜を保存して一時停止し、その試験の正式判定は条件逸脱が未解決の間は保留とする。都合の悪い手を再計算して置き換えない。

強制手はAPIを呼ばない。勝敗と棋譜にはそのまま含め、API呼出しが少ない対局を後から除外しない。合法候補数・入力サイズの上限を超えた場合も、Jevなしへ黙って切り替えず技術停止とする。

## 5. 失敗・中断・再開

タイムアウトや不正回答で通常AIに代替させて対局を続けない。比較対象の処理を変えず、その局面・要求・応答を保存して停止する。

| 状況 | 扱い |
| --- | --- |
| タイムアウト、通信エラー、HTTP 429／5xx、不正JSON、不正回答 | 保存して一時停止。同じ入力への追加試行は最大1回 |
| 追加試行の開始 | 通常の再開コマンドによる明示的再開。自動再試行しない |
| 再試行間隔 | 最低60秒。Retry-Afterがより長ければ従う |
| 2回とも失敗 | この版では3回目を送らず、試験を技術中断として保持 |
| モデル不一致、認証・不正要求など他の4xx、台帳・ハッシュ不整合 | 原因確認まで停止。通常の再開で解除しない |
| 有効回答だがusage欠落 | 最大予約額を保持して利用可能。不明費用を明記 |
| usageが予約上限を超過 | 費用異常として停止 |
| ユーザーの手動中断 | 現在の手を保存して停止し、同じ局面・対局順から再開 |

1論理要求にattempt番号を付け、失敗分も含めすべての通信を個別に予約・計上する。同じattemptは再送しない。有効回答が保存されていれば再開時にその回答を使う。新しい回答を取り直して好ましい方を選ぶことはしない。他の対局で同じ局面が出た場合のAPIキャッシュ共有は行わない。

## 7. 棋力判定の方法

主指標は勝敗であり、統計上の単位は開始局面ごとの2局1組とする。同じ開始局面から担当側を入れ替えた対局をペアとして扱う考え方を採用する。[対局ペアの統計モデル](https://github.com/vdbergh/pentanomial)

Jev側から見て、2勝0敗の組数をA、0勝2敗をB、1勝1敗をCとする。全32組終了時にA+B+C=32となる。全対局の勝率は(2A+C)/64で報告する。

主検定は、非同点組N=A+Bに対する**両側の正確二項検定、有意水準5%**とする。帰無仮説は「非同点組でJev側が2勝する条件付き確率qが1/2」。p値は`min(1, 2 × BinomialCDF(min(A,B); N, 0.5))`とする。N=0ならp=1とする。[二項検定と正確な区間推定](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binomtest.html)

この方法は、独立に生成した開始局面の組を標本とみなすモデルに基づく。ゲームの各手や64局をそれぞれ独立した標本として水増ししない。実装には本計画の式と照合した計算を用いる。

| 条件 | 判定 |
| --- | --- |
| 全64局有効終局、条件逸脱未解決なし、p≤0.05、A>B | この条件でJev併用の優位を確認 |
| 同じ前提、p≤0.05、A<B | この条件でAI-GEN4単独の優位を確認 |
| 同じ前提、p>0.05 | 判定不能。互角・同等と断定しない |
| 未完局、未解決の実装・時間・整合性の問題あり | 試験未完了／正式判定保留 |

95%の正確二項信頼区間をq=A/(A+B)について併記する。これは「非同点組でJev側が2勝する確率」の区間であり、1局単位の勝率の信頼区間とは呼ばない。N=0ではqを推定できないと表示する。1勝1敗の組も勝率と成績表からは除かない。

例としてA=10、B=2、C=20なら40勝24敗、p≈0.03857。A=9、B=3、C=20なら38勝26敗でもp≈0.146で判定不能となる。実際の組構成によって同じような総勝率でも不確かさが異なる。その他の検算例はstatistical-examples.jsonに保存した。

64局は大きな差を見つけるための初回規模であり、わずかな改善を判定できる保証はない。途中の勝ち越し・p値・深度を理由に終了や延長をしない。開始時に決めた64局を集め、最終判定は1回だけ行う。予算・障害による停止は別扱いとして全記録を残す。判定不能でも自動的に局数を追加しない。

段階別成績、担当player別成績、探索深度、ノード数、着手一致、Jev提案と最終着手の一致、応答待ち時間、再試行数、費用は補助指標として記録する。補助指標で主検定の判定を覆さない。Eloを主指標にしない。
