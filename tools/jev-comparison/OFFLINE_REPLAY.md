# 保存済み局面による探索時間枠の再生比較

この追加版はAPIを呼び出しません。APIキーは不要です。Jevの正式採用、本番変更、v3対局の再開、費用台帳の再開・変更は行いません。

## 比較する内容

v3の保存済み64要求（正常61、タイムアウト3）をすべて使い、同じ局面をAI-GEN4とJev併用側で探索します。強制手8件は問い合わせがなく探索順序を選べないため対象外です。途中停止局の8要求は含め、都合のよい正常局面だけには絞りません。

- 基準側の探索時間枠は2,000msです。
- Jev併用側は、その局面のv3棋譜が保存した`stats.allocatedTimeMs`を使います。範囲は約436.34〜1,649.49msです。正確な範囲はpreflightに表示します。
- 元の2,000msから記録済みの探索枠を引いた値を、観測された探索前消費時間とします。API待ちだけでなく入力準備や課金・応答記録の時間を含みます。
- 正常回答は再検証してから元の確率を使います。タイムアウト3件は確率を使わず、約0.44秒の枠で通常探索します。
- 最大深度は双方12です。ルール、評価器、公開AI、探索方式はv3から変更しません。
- 実行順は局面ごとに交互にし、各エンジンは同じ初期局面・深さ2で準備します。

過去の消費時間を予算として差し引くだけで、実際の待機やネットワーク通信は行いません。基準側も候補側も比較対象は探索そのものです。元の実対局で発生したすべての処理を再現する測定ではありません。基準側に2,000msの探索枠を与えるため、元の基準側の微小な準備時間は差し引いていません。これを実通信込みの対局勝率や通信安定性の測定と混同しないでください。

## 実行手順

元のキットとすべての追加版・結果がある実験用ブランチで、ZIPをリポジトリ直下に保存して実行します。ソース、計画、v3停止結果、各棋譜と入力・応答をハッシュ等で照合します。

```bash
cd "$HOME/github/bao-la-kiswahili-game" &&
python3 -m zipfile -e bao-jev-offline-comparison-v1.zip . &&
node tools/jev-comparison/offline-replay.cjs preflight &&
node tools/jev-comparison/offline-replay.cjs run
```

APIキーと`--live`は使いません。通信を行うコードを持たず、CLIではfetchも禁止しています。費用台帳を読み込んで費用を予約・確定する処理はありません。同時実行を防ぐため、既存のロック機構だけは共有します。

64局面を1プロセスで順番に比較します。通常は約4分以内が目安ですが、起動・保存・OSの状況により前後します。各局面の両側の探索が終わるたびに保存します。途中で止める場合はCtrl+Cを1回押し、現在の1局面の保存を待ってください。同じrunコマンドで未完了分から続けられます。完了済みの比較は再実行しません。

正常終了時は`OFFLINE-REPLAY-COMPLETE`です。終了または停止後は、結果をまとめます。

```bash
python3 -m zipfile -c bao-jev-offline-comparison-results.zip tools/jev-comparison/results
```

結果ZIPと最後の出力を共有してください。この段階で有料コマンドを実行する必要はありません。

## 記録と解釈

新しい結果は`results/offline-replay-v1/`に保存します。旧v3の結果を変更しません。plan.jsonに条件、inputs.jsonに64局面と固定した時間枠、positions/に各比較、summary.jsonに集計を保存します。中断・再開時は各結果の入力と時間枠を照合します。

集計は候補側がより深く読めた局面数、同じ深度の局面数、浅くなった局面数、選択した着手の一致数です。正常応答とタイムアウトも分けます。異なる深度で得た評価値の大小を優劣判定に使いません。ノード数が少なくても、読めた深度が浅ければ探索効率改善とは限りません。

これは予備対局に由来する相関のある標本を使う事後比較です。新しい独立した標本ではなく、正解判定器もありません。局面全体・Jev全般への一般化はできません。元の応答・遅延を固定するため、新しいAPI呼び出し時の挙動を予測できません。

v3RecordedBudgetは今回確認したv3停止時点の費用スナップショットです。この無課金コマンドの費用は0で、別途のAPI利用や最新請求書を取得する機能はありません。
