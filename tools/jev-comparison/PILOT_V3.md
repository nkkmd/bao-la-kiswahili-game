# Jev 予備対局 v3

この追加版は比較と記録専用です。Jevの正式採用、本番への反映、AI-GEN4の変更は行いません。

## 診断結果と変更理由

v2の第1局は26手終了後、次の要求に対するHTTP 200の回答が検証に通らず停止しました。当時のクライアントは不合格項目と数値を保存していなかったため、元の異常の原因は確定できません。

同じ入力に対する追加診断1件は全検証に合格しました。6候補の確率は0.02、0.01、0、0、0.91、0.06で合計1、最大確率の候補を選択し、confidenceは0.9でした。これは新しい回答であり、元の異常の復元ではありません。診断回答のfatal:trueは、診断中も台帳の停止状態を維持した結果です。

v3は確率の許容範囲を広げません。元のcore.cjsのvalidateResponseをそのまま使い、不合格の回答は探索に渡しません。不合格項目、候補ごとの数値・型、確率合計、課金用usageを保存し、その手の残り時間でAI-GEN4の通常探索を行います。追加の診断専用API要求や自動再送は行いません。

## 固定条件と停止条件

対象はjev-1.13.0、AI-GEN4 expert、1手全体2,000ms、API待ち上限1,500msです。入力作成、通信、記録、通常探索を全体時間に含め、同期処理による超過は棋譜に記録します。Jevの有効な回答はルートの探索順序にのみ使用します。

既に固定した4開始局面を両方の担当側で実行し、計8局を新規に開始します。各局は最大256手です。旧v2の26手は保存したまま、別のpilot-v3ディレクトリに記録します。以前の条件の棋譜と成績を合算しません。この段階は接続と対局動作の予備確認で、正式測定ではありません。

- invalid-responseとinvalid-json、タイムアウト、ネットワーク失敗では、その回答を使わず残り時間で通常探索します。
- Jev側で代替処理が3回連続したら予備対局を停止します。正常応答または強制手で連続回数をリセットします。手動中断を挟んでも回数を引き継ぎます。
- モデル不一致、HTTPエラー、予約上限を超える報告使用量では台帳を停止します。
- 予算上限に達する次の要求は送信せず、対局を停止します。
- 不合格数、代替処理数、未完局、時間超過も比較結果に含めます。不合格を勝敗だけで隠しません。

## 予算と確認後の再開

確認済み時点は42要求、累計計上$0.011167170です。内訳は報告使用量からの計算$0.002909634と、過去3件のタイムアウトに対する未確定予約$0.008257536です。提供元の請求額を確定する数値ではありません。未確定予約を戻したり、予算を初期化したりしません。

全体の作業上限$4.50、総上限$5、予備段階の累計上限$0.40を維持します。新規要求の直前に従来と同じ最大使用量分を予約します。途中終了した要求も再送しません。

現在の台帳にはinvalid-responseによる停止があるため、実行時には`--acknowledge-reviewed-resume`を指定します。この指定で、確認済み停止のハッシュ、追加診断、42要求の費用を照合し、同じ追記式台帳にreview-resumeを1件記録します。過去の停止行や費用は変更しません。許可範囲はこの版の4組8局だけです。この指定で、その後の新たな停止を解除することはできません。

再開記録を追加すると旧版の台帳読込処理は未知の記録形式として停止します。以後の実行と費用確認にはpilot-v3.cjsを使ってください。旧run.cjs、pilot-v2.cjs、診断コマンドを再実行する必要はありません。台帳や結果を削除して再開しないでください。

## ローカル実行

元のキット、遅延診断、pilot-v2、応答診断、および各結果が揃った実験用ブランチで実行します。既存のファイルのハッシュ、基準コミットとGitの状態をpreflightで確認します。APIキーは環境変数TYPESAFE_API_KEYを使用し、ファイルには保存しません。

ZIPをリポジトリ直下に置き、まず次を実行します。APIを呼び出さず、台帳も再開しません。

```bash
cd "$HOME/github/bao-la-kiswahili-game" &&
python3 -m zipfile -e bao-jev-pilot-v3.zip . &&
node tools/jev-comparison/pilot-v3.cjs preflight
```

PASSのときだけ、同じターミナルで次を実行します。このコマンドから課金対象の要求が発生します。

```bash
node tools/jev-comparison/pilot-v3.cjs run --live --acknowledge-reviewed-resume
```

キー未設定と表示されたときだけ、シェル履歴にキーを残さず読み込みます。

```bash
read -rsp 'Jev API key: ' TYPESAFE_API_KEY &&
printf '\n' &&
export TYPESAFE_API_KEY
```

任意の手動中断にはCtrl+Cを1回押し、その手の保存を待ってください。手動中断後は同じ実行コマンドでチェックポイントから続行できます。3連続代替処理による停止、新しい技術停止、予算停止の場合は、その結果を共有して確認します。

費用だけを確認するコマンドです。実行中のプロセスが終了してから使います。

```bash
node tools/jev-comparison/pilot-v3.cjs status
```

終了または停止後、結果一式をまとめます。APIキーと.git内の台帳は含まれません。費用の集計と再開記録の参照ハッシュはsummary.jsonに含まれます。

```bash
python3 -m zipfile -c bao-jev-pilot-v3-results.zip tools/jev-comparison/results
```

このZIPと最後のターミナル出力を共有してください。正式測定の実行や採用判定には進みません。

## 検証方法

実APIを呼び出さないテストで、厳格な検証と不合格時の代替探索、対局と中断・復元、費用の継続、再開範囲、停止条件を確認します。API応答とCLIのGit確認は模擬します。テスト用に再構成した台帳は日時によりハッシュが実台帳と異なるため、テストコピー内だけ停止ハッシュを置き換えます。配布版には確認済みの実停止ハッシュを固定しており、実Git・実台帳の照合はユーザー環境のpreflightが担当します。

2026-09-21のオフライン検証は36項目PASSです。模擬対局8局・288手、従来探索との同一性12局面、過去の正常応答38件を確認しました。実API要求は0件です。CLIの明示的再開からモデル不一致による再停止まで、および新しい停止を同じ指定で解除できないことも模擬環境で確認しました。
