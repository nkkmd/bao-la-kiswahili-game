# JevとAI-GEN4のローカル比較 — 準備・予備試験キット

このキットは、Baoの現行AI-GEN4へJevによる探索順序の提案を加え、性能と費用を調べるための実験専用プログラムである。**結果にかかわらず正式採用・公開配信・AI世代の更新は行わない。**

現在は準備と予備試験の段階であり、実APIの接続確認と性能測定は未実施である。最初に無課金の`preflight`だけを実行し、その結果を共有する。正式測定は、実際の入力使用量・応答時間・対局長を確認して件数を固定した後に、別の段階として追加する。この版に正式測定を開始するコマンドはない。

## 最初の実行

配布ZIPには`tools/jev-comparison/`以下だけが入っている。リポジトリのルートへ展開する。既存の`public/`を上書きするファイルは含まれない。

次のコマンドはAPIへ接続しない。キーを設定していても通信しない。

```bash
cd "$HOME/github/bao-la-kiswahili-game"
node tools/jev-comparison/run.cjs preflight
```

成功すると`status: PASS`、実API呼び出し0回、今回のAPI費用0ドルが表示される。次のファイルを共有する。

```text
tools/jev-comparison/results/preflight.json
```

内容はOS、CPU、Node.js、メモリ、固定コードのハッシュ、模擬検証結果、短い探索の所要時間である。環境変数全体、APIキー、ホスト名、ホームディレクトリ名はこの報告へ保存しない。

## 探索への組み込み方

合法手は`BaoEngine.moveVariantsForSearch`で、nyumbaの使用／停止や方向の違いを含めて列挙する。各候補の着手後局面も同じエンジンで計算する。盤面、手番、持ち石、nyumba、終局状態、局面段階、座標の定義と短い採用ルールをJevへ渡す。質問文は英語で固定している。これはAPIへ渡す機械処理用の入力であり、日本語の説明本文とは区別する。

Jevの`Choice`の候補別確率を、探索の出発点の着手順序だけに用いる。既知の即勝ちを最優先し、その後はJevの確率が高い順、同値の場合は既存の順序とする。すべての候補を保持し、Jevによる候補の削除は行わない。既存のアルファベータ枝刈りは継続する。葉の評価器、ルール、終局判定は変更しない。確率とconfidenceを実際の勝率や正解保証として解釈しない。

元のファイルをメモリへ読み込み、候補側に探索順序の処理を追加する。両側には共通の外側の期限を渡す処理を追加し、元コードで期限設定の前に行われる準備処理も時間に含める。元のソースファイルは書き換えない。挿入位置が一意でない場合や固定ファイルのハッシュが違う場合は停止する。

時間には候補生成、入力作成、API通信、応答検証、費用記録、探索を含める。対局記録の保存は着手測定の外側で行う。Jev側は待ち時間ぶん探索時間が短くなる。残り時間がない場合は両側共通の合法な既定手を返す。同期処理の1回の局面遷移などで期限を少し超える可能性があるため、超過時間を記録する。OSレベルで厳密に2,000msで打ち切る仕組みではない。

候補が1つなら問い合わせない。候補数が255を超える場合や入力が28,000バイトを超える場合は、その着手でJevを使わず既存探索を続け、理由を記録する。確定した勝敗をJevに再判定させない。

## 予備試験の範囲

費用を抑えるため、予備試験は16局面と4組8局を固定した出発点とする。従来の64局面・16組という初期案から縮小した。予備局面はnamuaとmtajiを8局面ずつ、異なる対局から生成する。一様方策と捕獲数を優先する方策を対局単位で使い分ける。予備対局の開始局面には別のseedを用い、同じ開始局面から担当側を入れ替える。

局面診断ではAPI回答を取得した後、両側を深度3、時間上限5秒で探索する。両側が深度3まで完了した場合の評価値の一致などを確認する。この探索時間はAPI待ち時間を含まないため、実用性能の成績には使わない。深く読んだAI-GEN4との一致も正解保証とは扱わない。

予備対局は開始局面から256着手で打ち切る。上限到達は`UNRESOLVED`（未決着）として保存し、引き分けや負けへ自動変換しない。ルールエンジンの連続種まき上限による終局は`ENGINE-LIMIT`として区別する。APIの代替処理が候補側で3着手続いた場合は、浪費を避けるため一時停止する。

予備試験は入力・時間・費用の診断用であり、正式測定へ合算しない。正式測定の件数、未使用局面、統計処理、停止条件は予備結果の確認後に固定する。正式対局では勝敗だけでなく、未決着、障害、担当側、組単位の不確実性を扱う。僅差を判定できない場合は、その限界を記録する。

## 費用の制御

2026年9月21日に確認した[公式モデル仕様](https://docs.typesafe.ai/models)では、入力100万トークンUS$0.042、出力は無料である。実行時もこの料金を前提とする。アカウントに別の料金が表示される場合や公式料金が変わった場合は、有料コマンドを実行する前に知らせる。

| 区分 | 枠 |
| --- | ---: |
| 接続確認 | $0.10 |
| 予備局面と予備対局の合計 | $0.40 |
| 後続の正式局面比較用 | $0.50 |
| 後続の正式対局用 | $3.50 |
| 実行枠の外に残す余裕 | $0.50 |
| 全体 | $5.00 |

通信前に、公式の1要求上限を保守的に65,536入力トークンとして、1回当たり$0.002752512を台帳へ予約する。予約を含めて当該区分または通常枠$4.50を超える要求は送信しない。正常な使用量が返った場合だけ、その入力使用量に基づく額へ更新する。通信切断、タイムアウト、使用量欠落、課金不明の失敗では予約額を保持する。これはサービス提供側の確定請求書ではなく、実験内の使用量と不明分を管理する台帳である。

単価計算は整数のナノドルで行う。自動再試行はしない。同じ要求IDを再実行した場合は保存済み応答を使うか、中断済みとして代替処理する。使用量が予約上限を超えた場合、モデルIDが違う場合、不正な応答やHTTPエラーがあった場合は停止する。提供側に強制利用上限がある場合は併用する。別プログラムからのAPI利用額はこの台帳には含まれないため、実験中のキーは本キットだけで使う。

台帳はGitの共通管理ディレクトリの`jev-comparison/JEV-BAO-COMP-20260921/budget.jsonl`に保存する。作業ブランチや結果フォルダーを切り替えても費用を忘れないための配置である。台帳は削除しない。結果ファイルにも予算集計を残す。台帳の改変や不完全な末尾を検出した場合は、リセットせず停止する。

## API接続へ進むとき

最初の無課金確認を共有した後、案内に従って以下の段階を実行する。キーはチャットへ貼り付けない。Bashの非表示入力によりキーそのものをコマンド履歴へ残さず設定できる。

```bash
read -rsp 'Jev API key: ' TYPESAFE_API_KEY
echo
export TYPESAFE_API_KEY
```

接続確認は最大1要求である。同じコマンドを再実行しても、新しい要求は送信しない。

```bash
node tools/jev-comparison/run.cjs smoke --live
```

予備局面と予備対局は、各段階の結果を共有してから順に実行する。

```bash
node tools/jev-comparison/run.cjs pilot-positions --live
node tools/jev-comparison/run.cjs pilot-matches --live
```

これらの有料コマンドは`--live`と環境変数の両方がなければ送信しない。APIキー、Authorizationヘッダー、サービスのエラー本文はファイルへ保存しない。記録するのは送信局面、候補、質問、必要な応答フィールド、使用量、遅延と処理状態である。実験後に環境変数を消す場合は次を使う。

```bash
unset TYPESAFE_API_KEY
```

## 中断と再開

`Ctrl+C`を1回押すと現在の着手を保存して一時停止する。2回押すと強制終了する。通常停止なら同じコマンドで続きへ進める。完了した局面と対局は再実行しない。

着手の途中で中断した場合、API応答が保存されていれば再送せず利用する。この着手には保存されたAPI待ち時間を探索時間から差し引くが、再起動前の全処理時間を完全に再現するものではない。`recovered`を記録し、通常の新規通信の遅延集計と区別する。応答のない中断要求は不明分の費用を保持して代替処理する。棋譜を再生し、保存局面と一致することを再開時に検証する。

状況確認は無課金である。

```bash
node tools/jev-comparison/run.cjs status
```

強制終了でロックが残った場合は出力を共有する。停止済みプロセスのロックだけを解除する機能を用意している。台帳は変更しない。記録されたPIDがまだ存在する場合は解除しない。

```bash
node tools/jev-comparison/run.cjs unlock
```

## 記録と再現

`results/preflight.json`は最初の確認結果、`smoke.json`はAPI接続結果、`summary.json`は予備試験の進捗と費用を表す。`positions/`、`games/`、`requests/`、`responses/`に詳細を保存する。`pilot-fixtures.json`とコードのseedから予備局面を再生成できる。

`source-manifest.json`に基準AIの7ファイルのSHA-256、`kit-manifest.json`に配布キットのハッシュを記録する。人間向け入口は本書、条件定義は`config.json`、実装は`core.cjs`と`budget.cjs`、実行は`run.cjs`、無課金検証は`selftest.cjs`で追える。機械用ID、JSONのキー、ソースコード中のAPI入力文、コマンドと正確な出力は原表記を保持する。

公開コード、main、既存研究の固定記録は本キットによって変更しない。GitHubへのpush、PR作成、main統合、公開配信を行う機能もない。作業は単一エージェントで行い、サブエージェントを使っていない。

配布前に実施した検証と未確認事項は[検証記録](VERIFICATION.md)にまとめた。
