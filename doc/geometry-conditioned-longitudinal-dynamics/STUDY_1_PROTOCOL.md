## 9. Primary endpoint definitions

### C1 — Directionality / path efficiency

For sequence `z_0..z_14`:

```text
net = d(z_0,z_14)
path = sum_{t=0..13} d(z_t,z_(t+1))
C1 = net / path
```

Undefined only if `path=0`.

Interpretation: chronology-conditioned path efficiency in the six-axis representation.

### C2 — Persistence / lag-distance gradient

```text
meanLag1 = mean_{t=0..13} d(z_t,z_(t+1))
meanLag4 = mean_{t=0..10} d(z_t,z_(t+4))
C2 = meanLag4 - meanLag1
```

A larger value indicates stronger short-lag geometric persistence relative to a 16-ply separation.

### C3 — Return fraction

For anchor `t=0..12` with `d(z_t,z_(t+1)) > 0`, define a return when:

```text
min_{j=t+2..14} d(z_t,z_j) < d(z_t,z_(t+1))
```

`C3 = return-anchor count / eligible-anchor count`.

This is threshold-free relative to the trajectory's own immediate departure distance. Undefined only if no eligible anchor exists.

### C4 — Chronology-conditioned circulation / operational hysteresis endpoint

For every coordinate pair `(a,b)`, `a<b`, compute the exact signed shoelace circulation of the ordered path closed by the straight segment from `z_14` back to `z_0`:

```text
twiceArea(a,b) = sum_{t=0..13}(z_t[a]*z_(t+1)[b] - z_(t+1)[a]*z_t[b])
                 + z_14[a]*z_0[b] - z_0[a]*z_14[b]
```

`C4 = sum_{a<b} |twiceArea(a,b)|` over all 15 axis pairs.

This is an operational geometry-space circulation/hysteresis-like endpoint only. It is not physical hysteresis under a controlled external parameter.

### C5 — First-order directional path dependence

For adjacent steps `Delta_t` and `Delta_(t+1)`, axis `j` is informative when both axis changes are nonzero.

Count across all `t=0..12` and six axes:

- `same` when the two nonzero changes have the same sign;
- `opposite` when they have opposite signs.

```text
C5 = (same - opposite) / (same + opposite)
```

Undefined only if `same+opposite=0`.

This is a first-order history/path-dependence endpoint; it does not establish causality.

## 10. Formal inference and multiplicity

For each primary endpoint `C1..C5`, each formal trajectory contributes exactly one contrast:

`delta_i = actual_i - controlMedian_i`.

Formal test per endpoint:

- exact two-sided binomial sign test;
- null positive/negative probability = 1/2;
- no checkpoint/window-level p-value;
- no trajectory weighting.

Minimum formal nonzero trajectory count per endpoint = **20**. Below this, that endpoint is `NON-ESTIMABLE`.

Family-wise multiplicity across the five primary endpoints uses Holm adjustment at family alpha `0.05 = 1/20`, implemented with exact rational p-values.

Per-endpoint decision family:

- `CONFIRMED` — estimable and Holm-adjusted exact p <= 1/20;
- `NOT-CONFIRMED` — estimable and Holm-adjusted exact p > 1/20;
- `NON-ESTIMABLE` — formal nonzero trajectory count <20 or endpoint definition unavailable in too many trajectories;
- `TECHNICAL-INVALID` — mandatory implementation/integrity contract fails.

For `CONFIRMED` endpoints, the exact median trajectory contrast sign is reported as `ACTUAL-GREATER`, `ACTUAL-LESS`, or `ZERO-MEDIAN`; this direction is descriptive and is not chosen after outcome inspection.
