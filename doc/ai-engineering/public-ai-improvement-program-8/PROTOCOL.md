# PBAI-P8 — 事前固定する検証条件

## 目的と比較対象

P7で高速化した学習済み評価器を変更せず、保存済み数値の比較契約を修正したうえで、新規データによりAI-GEN3を同じ持ち時間で強化できるかを独立再検証する。主候補は`PBAI-C015-v1`。比較対象は現行AI-GEN3と、同じモデルを使うP6の旧推論実装である。

モデルは[MODEL.json](MODEL.json)に固定した。元のPBAI-C012-v1のモデルとbyteが一致し、SHA-256は`565147bdc4c62ddc2888af2cc7bb43c7ef192d68c8c8beb76054c8c738a2c637`。再学習、学習データ追加、係数の再調整、整数化の変更、候補の交換はしない。旧モデルの利用は既知の開発情報の利用であり、P6データを未知の検証標本として扱わない。

## 維持する最適化

1. 16真理値表を対応するAND、OR、XOR、NOT等の式へ変換する。
2. 定数入力、同じ入力、単項演算、二重否定を厳密に簡略化する。
3. 入力の交換と真理値表の対応を保持して共通の演算を共有する。
4. 読み出しへ影響しない演算と、ゼロ・相殺される整数係数を除く。
5. 使用する入力bitだけを盤面から直接抽出し、399要素の入力配列作成を省く。
6. 非終局の状態検証を両視点で共有し、一回にする。

状態や学習データを見て「通常は0」と推測したbitを定数扱いしない。入力範囲、符号化の意味、clip、整数化、両視点の差、終局処理は保持する。整数係数の集約がJavaScriptの安全な整数範囲内であることを確認する。対象は基準エンジンの正しい形状の局面であり、範囲外・不正な形状は拒否する。

モデル読込後の構造検査では、1,536ゲートから実行時589ノード、入力327bit、読み出し329項へ整理された。これは計算グラフの構造量であり、実測速度の証拠ではない。

## 技術的な条件

全16真理値表の4入力組、固定乱数の4,096個の人工Booleanベクトル、標準初期局面と既知戦術fixtureで、別記述の真理値表評価との完全一致を要求する。変更した切片が不一致として検出される負の対照、ゼロ読み出し、pendingの32bit境界も確認する。人工ベクトルはBao到達局面の棋力証拠ではない。

新規の採用root全件では両視点の評価値が旧モデルと完全一致し、D2・D3の時間制限なしの探索で、着手とelapsedMs以外の全統計が旧推論実装と一致することを要求する。原状態の非破壊も確認する。局所変換と測定対象での一致を確認するもので、形式証明器による全プログラムの証明とは呼ばない。

不一致は`TECHNICAL-INVALID / HOLD`。結果を見て機構を修正し、同じ評価集団で取り直すことはしない。

## JSON保存後の数値比較契約

P7はJSON保存で−0が0へ変わることを検算が許容せず、`TECHNICAL-INVALID / HOLD`となった。P7の成績と診断を既知の開発情報として扱い、その正式判断を変更しない。

保存済み評価値と再計算値は、双方が有限のnumberであることを要求し、JavaScriptの数値比較`===`で一致を確認する。+0と−0だけを同じ数値ゼロとして扱う。許容誤差は0であり、最小の正数を含め実際の値の差は拒否する。NaN、±Infinity、null、文字列、undefinedは拒否する。実行中の新旧モデルのraw出力と固定深度探索の比較はP7の厳密な条件を維持する。

回帰試験は±0、正負の整数・小数・最小値のJSON往復、数値差と非有限値を含む負の対照、および[JSON_ZERO_FIXTURES.json](JSON_ZERO_FIXTURES.json)のP7既知局面で行う。この1局面はP7の追加検算で新旧評価値の2比較に符号差を生じた既知の診断入力であり、新規の棋力証拠には数えない。

[SPEC.json](SPEC.json)を数値の正本とする。生成方針、RAW識別、12手prefix、phase別の最初の適格root、8192 seedの上限はP6と同じ方法を使う。標準初期局面から合法variant一様選択、最大96手、Namuaは12〜40手、Mtajiは44〜88手、合法variantが2以上の非終局rootを1系列から一つ採用する。

| 開発用評価 | 851000001 | 各phase64、計128 root |
| 独立検証用評価 | 852000001 | 各phase64、計128 root |
| 開発用対局 | 853000001 | 各phase16ペア、計64局 |
| 独立検証用対局 | 854000001 | 各phase32ペア、計128局 |

統計再標本化は856000001、技術用Booleanベクトルは857000001。既存記録を検索し、これらの新規生成先頭seedの使用記録はなかった。検索で一致した既存の小数点以下の所要時間はseed記録ではない。

[KNOWN_IDENTITIES.json.gz](KNOWN_IDENTITIES.json.gz)はP6までの既知除外情報、P7の全採用／棄却sourceのRAW・12手prefix・全系列hash、P7の採用source系列と全704対局で訪れた状態のRAWを含む。計67,532の識別情報行を固定する。P7の608採用sourceと全対局の計55,971遷移を再生して追加RAWを取得した。生成元archiveのhashは[SPEC.json](SPEC.json)に固定した。

新規split内外でもRAW、prefix、全系列hashを重複排除する。P6・P7の既知集団と未使用予約blockは使用しない。生成・棄却・採用をすべて保存する。P7より既知RAWの除外範囲が広いことを明示し、同じ固定方針による新たな評価集団として扱う。標準初期局面や12手未満の共通prefix、未採用状態での合流まで独立とは主張しない。

教師はAI-GEN3の固定D3のrootScoreを1024で割り[-1,1]へclipする。近似探索値であり、勝率や真の価値ではない。学習には使わず、新しい集団での誤差を評価するためだけに生成する。

## 速度・誤差・戦術の条件

開発用と独立検証用の各段階で、次をすべて要求する。

- 主候補と旧推論の評価値・固定D2/D3探索の不一致0。
- 主候補の教師に対する平均二乗誤差が、現行静的評価の1.10倍以下。
- AI-GEN3に対する評価時間比のphase別中央値が0.90以下、全root比のp95が1.10以下。
- 旧推論に対しても、評価時間比のphase別中央値が0.90以下、全root比のp95が1.10以下。
- 現行AI-GEN3と主候補が既知戦術8件を通過する。

各root・方式で2回warmup後、20評価を1反復として6反復する。方式順はrootと反復によって循環させ、単一プロセスで計測する。直接入力抽出、状態検証、両視点の推論を含め、強制GCはしない。root別反復中央値の比を集計する。構造量の削減だけを速度改善と呼ばない。

不成立なら当該段階の`DEVELOPMENT-GATE-FAIL / HOLD`または`VALIDATION-GATE-FAIL / HOLD`で終了し、後続splitは生成しない。

## 対局と棋力判断

速度・誤差・戦術・正確性が成立した主候補をAI-GEN3と比較する。両者hard/bao/phase2、軽量遷移有効、100ms/D8。同じrootで担当sideを交換して2局1ペア。最大160手で未終局のみ引分0.5、winnerは1/0点。ルール、探索、既存の期限開始位置は変えず、探索関数全体の実時間も保存する。

開発用・独立検証用は全体勝点率0.45以上、各phase0.35以上、illegal/crashなし、150ms超過率の現行からの増加0.05以下を次の条件とする。未達は当該段階のHOLDで閉じる。部分成績で標本数を変えない。

最終は512局・各phase128ペアを完了し、重複対局系列で連結したclusterが200以上であることを要求する。phaseを保つcluster bootstrap 10,000回で、勝点率0.53以上、両側95％区間下限が0.50超、各phase0.45以上、運用条件通過なら`STRENGTH-IMPROVED-IN-FROZEN-DOMAIN`。未達は`STRENGTH-IMPROVEMENT-UNCONFIRMED / HOLD`。主張はNode/Linuxの100ms/D8の範囲に限定し、標準500msやスマートフォン実機の棋力へ一般化しない。

## 実行と独立検算

開始前に契約と全依存ソースをcommitしてGitHubへ保存する。単一の外側Python監視器が、生成・測定・独立検算・最終判断を連続4時間で監視する。Node heapは2048MiB、単一測定とし、学習は実行しない。

別記述の乱数によるsource再構成、保存済み着手の合法性・終局・得点の再生、同じ基準AIによるD3教師再計算、保存済みD2/D3一致の再検算を行う。指標・判定・対局統計は別のPython処理で再集計する。同一ルールエンジンを信頼基盤とする検算であり、ルールの独立再実装ではない。時間制限付き対局は再測定しない。

開始markerの排他的作成、完成済みファイルの上書き拒否を維持する。資源超過、プロセス中断、検算不一致は`TECHNICAL-INVALID / HOLD`。生存している監視器はチャット中断中も継続できるが、死亡後に開始markerを削除してやり直さない。終了後はarchive・hash索引・開始markerをGitへ保存する。

公開判断は全結果にかかわらず`NO-RELEASE / KEEP-AI-GEN3`。今回の検証はmain統合、公開配備、正式採用、AI世代昇格を含まない。P6・P7のHOLDと凍結済み記録を変更しない。
