# PBAI-P7 — 最終報告

## 正式判断

正式状態は`COMPLETE / TECHNICAL-INVALID / HOLD`。論理ゲート推論の高速化と良好な対局成績を観測したが、事前に必須とした検算が停止したため、本Programによる正式な棋力改善認定は行わない。公開判断は`NO-RELEASE / KEEP-AI-GEN3`である。

## 目的と実装

P6の学習済み論理ゲートモデルを固定し、AI-GEN3の探索へ同じ評価値をより低い計算負荷で供給できるか調べた。主候補は`PBAI-C015-v1`。学習済みモデル、入力bitの意味、整数化とclip、ルール、探索方式を保持した。

16真理値表の演算別変換、定数・単項・二重否定の簡略化、共通演算の共有、不要演算の除去、整数読み出しの集約、必要な入力bitの直接抽出を実装した。元の1,536ゲートから、実行時589演算、入力327bit、読み出し329項へ整理した。全16真理値表、4,096人工Booleanベクトル、既知9局面と固定D2探索、負の対照、pendingの32bit境界を確認してから、新規評価へ進んだ。

実行前に条件とソースをcommit `89276ddf1fcb06f313403028901c417867755a6a`としてGitHubへ保存した。モデルSHA-256は[SPEC.json](SPEC.json)を正本とする。P6のモデルとbyteが一致し、再学習は実施していない。

## 検算停止と原因調査

正式検算は`verify-pbai-p7.js:78`で、JSONから読んだ`0`と、再計算した`-0`を厳密比較して停止した。JavaScriptの`Math.trunc`は負の微小値から`-0`を生成するが、JSON保存では`0`となる。Nodeのstrict assertionはこの符号差を区別する。実行監視器は事前条件どおり`TECHNICAL-INVALID / HOLD`を保存し、正式なPython集計は実行しなかった。

元の実行コードと最終結果は変更していない。終了後、元の検算を基に、数値ゼロの符号差だけを許容する別の原因調査スクリプトを作成した。新規の局面集団、時間測定、時間制限付き対局は追加していない。保存済みsourceの再構成、固定D3教師の再計算、棋譜再生を再び行った。

追加検算は採用608局面、教師256局面、全704局・20,318手、固定深度512比較を照合した。ゼロ符号差は2件で、それ以外の照合は通過した。別のPython集計でも保存済み指標と一致した。両方の追加結果には`diagnosticOnly: true`と`formalDecisionUnchanged: true`を付けた。

追加集計JSON内の`final.decision`は、同じ数値判定式を保存済み成績へ適用した参考出力である。Programの正式判断は[final-result.json](../../../artifacts/pbai-p7/final-result.json)だけを正本とし、追加結果の成功で上書きしない。検算器の修正後に既存holdoutを再利用して正式成功へ変更することも行わない。

## 保存と次の判断

全体監視実行は1,814.289秒で終了した。原因調査は終了後の別処理であり、この所要時間や正式実行には含めない。元の生記録と追加調査を識別できる名前で保存し、計382ファイルをhash索引付きarchiveへまとめた。凍結依存30ファイル、P6の記録、public配下を保持した。

今回の観測は、同じモデルの推論軽量化に価値があり得ることを示す開発上の材料となった。正式な再検証を行うなら、JSON往復での数値比較契約と回帰試験を先に固定し、P7を既知情報として扱う別Programで新規seedを使用する必要がある。P7自体の取り直しはしない。

対象は単一Node/Linux環境の100ms・最大深度8に限る。スマートフォン、ブラウザ、標準500msでの速度や棋力は未確認である。main統合、公開切替、正式採用、AI世代昇格は実施していない。
