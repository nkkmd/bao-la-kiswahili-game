# 工程4のAI検証条件

固定日: 2026-10-08

## 目的と範囲

takasia対応で公開AI-GEN4の探索経路が合法に動作し、公開と同じ時間予算で応答することを確認する。評価器モデルのbyteを維持する。棋力向上や全局面の最善手の保証を主張する試験ではない。

入力は既存P9の既知9局面、E30、E30の先後交換、所有中nyumba開始の構成例の計12局面とする。既知局面は過去の開発で使用済みであり、未知の独立評価集団として扱わない。構成例の到達可能性を主張しない。

## 実行条件

- 世代はAI-GEN4、評価器はPBAI-C015-v1を維持する。旧公開release IDは系統の参照として保持し、対応改訂を`AI-GEN4-TAKASIA-001`で区別する。本番配信の採用記録ではない。
- ルール改訂は`BAO-RULES-V0.2.0-TAKASIA-001`。旧エンジンとの勝率比較は行わない。
- hard・expertの低・標準・高の3予算、各1回、12局面で計72条件。
- 乱数seedは`1008`。現在の公開設定を使い、時間予算・深さ・軽量遷移・quiescence設定を試験だけの都合で変更しない。
- 処理時間は実行環境に依存する。GitHub ActionsのNode.js 24とrunner情報、入力・コードのSHA-256を保存する。
- 比較用に同じ新エンジン・同じ評価器で深さ3・quiescenceなしの全幅minimaxを計算し、選んだ手の有限深さの損失を記述する。これは公開探索のquiescenceや深い読みの真値ではなく、最終勝敗の証明でもない。

## 合格条件と解釈

必須条件は72条件すべて完了、入力不変、返した手を新エンジンで適用可能、改訂識別一致、即時勝ちが可能なら即時勝ちを選ぶこととする。時間上限は探索内部の予算で、厳密な応答締切ではない。計測した探索時間が各条件で`max(予算×1.5, 予算+250ms)`を超える場合は性能上の未解決として記録する。この許容範囲は結果を見る前に固定し、失敗後に拡大しない。

全幅minimaxの有限深さ損失は、負になった場合は実装不一致としてFAIL、0以上は記述値として保存する。正の損失が出ても直ちに棋力低下やモデル再学習の必要性へ読み替えず、手・盤面・予算・深さを特定して考察する。

長めの計測はActionsを第一候補とし、1条件ごとにJSONLへ追記する。中断時にもartifactを保存する。再開は同じ入力・コードhash・計測環境に限り完了した条件を飛ばし、異なる条件の結果を混ぜない。部分実行は72条件の完了と区別する。

## 検証の分担

`test/takasia-ai.test.cjs`は12局面の全難易度・Worker相当・直接・通常／軽量・切戻しと、深さ2の全幅minimax・改訂拒否・旧凍結参照を確認する。実Worker threadの確認は`test/takasia-ai-worker.test.cjs`で行う。メイン画面の受理関数も実コードを抽出して試験するが、DOM・ブラウザー・実機の総合検証は工程7に残す。

再現は次で行う。

```bash
node --test test/takasia-ai.test.cjs test/takasia-ai-worker.test.cjs
node tools/takasia/benchmark-ai.cjs artifacts/local/takasia-ai
```

結果と限界は工程4の実装記録へ追記する。旧モデル・凍結棋譜・過去の結果・期待値を書き換えず、新ルールの証拠を別に保存する。
