# takasiaの採用仕様と影響範囲

## 固定した参照と採用判断

参照版は[ガイドv0.2.0の固定コミット](https://github.com/nkkmd/bao-la-kiswahili-ja/tree/aad9fda3ffb12c2ca785509951c71ce8a42bef5a)とする。旧固定参照から2コミット、39ファイルの差分を確認した。本文の主要変更は第05〜10章にある。[mtaji本文](https://github.com/nkkmd/bao-la-kiswahili-ja/blob/aad9fda3ffb12c2ca785509951c71ce8a42bef5a/guide/06-mtaji.md#takasia)、[採用記録](https://github.com/nkkmd/bao-la-kiswahili-ja/blob/aad9fda3ffb12c2ca785509951c71ce8a42bef5a/docs/drafts/takasia-adoption-20261008.md)、[完全局面E30](https://github.com/nkkmd/bao-la-kiswahili-ja/blob/aad9fda3ffb12c2ca785509951c71ce8a42bef5a/guide/examples/README.md#e30-takasia対象穴でrelay-sowingを止める)を基準とする。

ガイドはR-001（de Voogt 1995）、後年の著者解説R-006、形式化資料R-002、補助資料R-009を比較して採用判断を行った。「1個だけの穴」の例外はR-006の補足に基づく。nyumbaから始めれば対象穴で続行できるという歴史的異説は採用しない。現在のすべての大会の統一裁定を確認したとの主張はしない。

## 成立条件

mtajiのtakataを正常に終え、まだ終局していない盤面を使う。直前の手を行った側を攻撃側、その相手を防御側と呼ぶ。

1. 防御側の最初の蒔きによる捕獲手が0件であることを確認する。
2. 同じ盤面で攻撃側がもう一度指すと仮定し、最初の蒔きによる捕獲候補を列挙する。
3. 相手前列の捕獲対象穴を重複除去し、ちょうど1穴であることを確認する。候補手数とは区別する。
4. その穴が次の例外に該当しないことを確認し、防御側の次の1手に対する対象を設定する。

捕獲候補は開始穴2〜15個、蒔き終点が元から占有された自前前列、向かいも占有された前列という条件で調べる。開始穴・方向から到達点を計算し、相手の応手後を先読みして成立を判定しない。判定には捕獲候補の専用計算を用い、着手適用から再帰的に成立判定を呼び出さない。

## 対象穴の例外

| 条件 | 扱い |
| --- | --- |
| 対象穴のketeが1個 | 対象外 |
| 防御側前列の唯一の占有穴 | 対象外 |
| 防御側前列で唯一2個以上ある穴 | 対象外 |
| 所有中のnyumba | 個数による機能停止とは区別して対象外 |
| 所有を失ったnyumba位置 | 通常の前列穴として判定 |

## 次の1手での作用と失効

- 対象穴からtakataを開始できない。
- 蒔きの途中で対象穴を通過するときは1個を加えて続行する。
- 最後の1個が対象穴へ入ると、到達後の個数にかかわらずそこで停止する。relayのために取り上げない。
- nyumbaから開始した蒔きにも同じ規則を適用する。
- 対象は、その防御側が1手を終えた時点で失効する。自動的に次の同側手番まで持ち越さない。
- その手自身が新しいtakasiaを成立させる場合は、古い制約を消費し、新しく判定した反対側の対象を設定する。
- namuaのtakataがmtajiへ移行しただけの場合、mtajiの捕獲手の終了後、終局後には新たに成立させない。

終局と連続成立の全ゲーム上の検証は工程3で追加する。限定計算が全終局条件を実装したという扱いにはしない。既存のrelay安全上限は実装保護の制約として別管理する。

## 局面表現と検証用インターフェース

工程3の候補エンジンに対し、次の表現を採用する。状態を明示し、同じ石配置から履歴を推測しない。

```js
state.takasia = null;
// または、防御側の次の1手にだけ有効な対象:
state.takasia = { player: 1, index: 3 };
```

`player`は制約を受ける側、`index`はその本人から見た前列0〜7である。対象は常に前列なので行は保持しない。成立元手番の番号を別に保存せず、着手適用が消費・再設定を行う。初期局面では必ずnullとする。旧局面データの欠落項目は旧ルールの識別と合わせて扱い、旧棋譜にtakasiaを自動適用しない。

検証用に`detectTakasia(state, attacker, previousMove)`を公開エンジンのAPIへ追加する。盤面・所有・手の種類から対象またはnullを返す純粋関数とし、入力を変更しない。`previousMove.phase`と`type`を確認し、`state.player`に依存して攻撃側を取り違えない。未実装のこのAPIと新状態を前提にした[候補検査](../../../tools/takasia/check-engine.cjs)は、現在のエンジンでFAILになる。

通常着手と`applyMoveForSearch`は、新状態、所有、終局を含めて同じ結果を返す。新たな成立・停止・失効の表示イベントを設計する場合も、ルールの判定はエンジンだけで行う。

## 座標とE30の受入条件

本人の前列indexは0〜7、向かいのindexは`7 - index`。Northの物理的な左右は本人の左右と逆になる。E30のa4は`{ player: 1, index: 3 }`、a5は所有を失った通常穴である。

Southの直前takataはA7の2個をA6・A5へ蒔く作例である。その後、Northの合法な開始穴はa8・a5の2穴、方向を含めて4手となる。

| North開始 | North本人の方向 | 蒔き回数 | 最後の穴 | a4最終個数 | 停止 |
| --- | --- | --- | --- | --- | --- |
| a8 | right | 1 | a2 | 2 | 空穴 |
| a8 | left | 5 | a4 | 5 | takasia |
| a5 | right | 2 | a2 | 2 | 空穴 |
| a5 | left | 10 | a3 | 6 | 空穴 |

全4応手の全穴の最終個数を固定データに保存し、JavaScriptの1個ずつの計算とPythonの商・余りによる計算で照合する。E30の出典付き盤面、逆算した直前手、構成した境界局面を区別し、標準初期配置からの到達可能性や最善性は主張しない。

## 新旧ガイド差分の確認と作業範囲

| 項目 | 確認結果・作業上の扱い |
| --- | --- |
| takasia | 不適用から対応へ進める主対象。1個例外、所有を失ったnyumba、判定盤面、1手の期間を明確化 |
| mtajiの16個以上 | 新ガイドでtakataの開始を原典照合済みとした。現行コードは捕獲2〜15個・takata2個以上を分けており、16個例を回帰へ追加する |
| namuaのnyumba停止 | 新ガイドが到達後6個以上を明示。現行コードも到達後6個条件を持つ。停止と所有の区別を維持 |
| namuaのnyumbaのみ・2個蒔き | 新ガイドは開始前6個以上を確定例とし、開始前5個の境界を未解決とする。現行`onlyHouse`分岐は個数条件を持たないため、差異と未解決境界を工程3で明記し、推測でtakasia対応に紛れ込ませない |
| mtajiへのnyumba所有持越し | 対象除外に直接関係する。mtaji捕獲時の所有喪失の主体・順序を追加検証する。E30の両側所有なしだけではこの境界を保証できない |
| 捕獲方向・終局 | 新ガイドは原典確認や説明を補強。既存回帰と照合する。全規則へ変更がないとの保証はしない |
| 終わらない手 | ガイドの競技規則とブラウザーの512回上限を区別する。今回に無限手の新裁定を追加しない |

## 更新が必要な経路

| 経路 | 必要な更新 |
| --- | --- |
| `public/engine.js` | 対象保持、成立・停止・失効、合法手、通常・軽量遷移 |
| `public/ai.js`・`ai-candidate.js` | 局面キーに対象を含める。探索で同じ石配置の制約有無を区別 |
| `public/ai-release.js`・Worker・`main.js` | 引渡し、古い応答の破棄、切戻し、改訂識別、実際の着手の再検証 |
| `public/logic-evaluator.js` | 入力にtakasiaがない現行モデルの限界を新ルール下で確認 |
| `public/game-record*.js`・`diagnostics.js` | 新状態の保持、ルール・形式の互換性、往復変換・再生 |
| 棋譜受信Worker | 旧版固定のルール・許可項目・canonical局面・再生検証を更新し、新旧棋譜を混同しない |
| 画面・図解・Service Worker | 日英説明、対象穴、停止理由、関連リンク、資産・キャッシュ更新 |
| 設計・採用・研究の入口 | 現在基準と旧版の固定結果を区別。過去成果の数値を変更しない |

AI-GEN4の評価器は維持して開始する方針だが、新状態を直接見ないため、合法に動作することと十分な棋力を持つことを別に検証する。独立計算の対象は限定したmtajiの非捕獲手で、全Baoの独立エンジンではない。
