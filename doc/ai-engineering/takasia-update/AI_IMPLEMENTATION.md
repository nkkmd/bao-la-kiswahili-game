# 工程4のAI実装と検証

更新日: 2026-10-08

## 現在状態

AI-GEN4のtakasia対応を作業ブランチへ実装し、局面識別、通常／軽量探索、Worker・直接実行、切戻しの回帰を通過した。12局面・hard／expert・3予算の72条件を[検証条件](AI_BENCHMARK_PROTOCOL.md)に固定し、Actionsで計測する。計測完了と判断は後で本書へ追記する。

main統合・本番配信は未実施で、棋譜・診断・受信・表示・配信資産の同期は後続工程である。

## 実装内容

局面キーにtakasiaの対象手番・indexとルール改訂`BAO-RULES-V0.2.0-TAKASIA-001`を含める。置換表と評価キャッシュの両方がこのキーを使う。状態に項目がない場合とnullは同じ制約なしとして識別する。

対応改訂は`AI-GEN4-TAKASIA-001`とする。公開世代はAI-GEN4を維持し、既存release IDは過去の系統として保持する。新改訂は探索統計へ付け、Worker応答のルール改訂と局面キーを照合する。古い応答は新しい直接実行へ戻し、思考中に変化した局面や取消済み要求は破棄する。

候補評価器・候補AIの取得失敗、候補だけが旧改訂、無効化による切戻しでは、現在の新ルールを使う基準探索へ戻す。古い基準AIやエンジンとの混在は拒否する。切戻しは評価器・探索構成を戻すもので、旧ルールへ戻すものではない。

PBAI-C015-v1のモデル・重み・探索設定は維持した。論理ゲートの入力にはtakasia自体の特徴がなく、葉評価の情報不足があり得る。新しい合法手・遷移を探索できることと、モデルの全般的な棋力が十分なことを区別する。

## 旧参照との不一致の切り分け

工程3のCIで異なった局面はP9の`namua-endgame`であり、標準初期局面ではない。探索先のmtaji捕獲で両側のnyumba所有を失う修正を、独立VM内で旧来の着手側だけの処理へ戻す対照確認を行ったところ、基準・論理ゲートとも過去の着手と統計へ一致した。実際のコードは新規定を維持し、旧期待値を更新していない。

過去のP9資産で既知9局面の18結果を再検証し、旧AI-GEN3 manifestの5資産も履歴からhash照合する。Workerの旧byteは`tools/takasia/history/ai-worker.js`へ保存した。既存の固定試験を削除・skipしていないため、現在の公開ファイルとの完全一致を求める旧CIは引き続き失敗する。工程7で旧資産の検証と現行改訂の検証を分けて同期する必要がある。

## 検証と限界

新規AI回帰は23件PASSである。12局面の各試験内で4難易度、候補の有効／無効、Worker・直接・通常／軽量の経路を照合し、改訂拒否、入力不変、モデル・候補取得失敗を確認した。実Worker threadで3条件を実行し、思考中もメイン処理のtimerが進むことを確認した。

takasiaの3局面では、キャッシュ有効／無効の深さ2探索を、置換表や枝刈りを使わない別の全幅minimaxへ照合した。これは限定深さの同じ評価器に対する計算一致で、完全解ではない。過去の既知局面は未使用の独立集団ではなく、棋力改善の証拠にはしない。

公開予算の性能と深さ3の比較値はActions結果を確認して追記する。DOM・ブラウザー・Android実機での総合確認は工程7に残す。
