# PBAI-P9：標準持ち時間・毎手Worker条件での最終報告

## 結論

同じ固定モデルPBAI-C015-v1は、Node/Linuxで毎手Workerを起動し、500ms・最大深さ8で対局する条件でもAI-GEN3を強化した。主要256局は151勝105敗、勝点率58.984375%、128クラスタの層別bootstrapによる95%区間は55.078125〜62.890625%だった。事前に固定した全主要条件と独立検算を通過した。

正式判断は `STRENGTH-IMPROVED-IN-COLD-WORKER-DOMAIN`、プログラムは完了である。この成功は公開採用の完了を意味せず、公開状態は `NO-RELEASE / KEEP-AI-GEN3` とする。

## なぜ追加検証したか

P8では100ms・常駐VMで強化を確認した。一方、公開アプリは毎手Workerを作成する。新しい起動条件と標準持ち時間でも効果が残るかを確認するため、P8とは独立した集団で追加試験を行った。

モデルを再学習せず、P7のゲート論理を静的JavaScriptとして生成した。候補のWorkerで実行時にnew Functionを使わず、基準側には候補モデルを読み込ませない。Nodeのworker_threadsからブラウザ用Workerと同じスクリプトを実行する。ブラウザのWorkerスケジューラそのものを再現する試験ではない。

主要試験のphase別結果は次のとおりである。先後を交換した2局を一つの単位とし、NamuaとMtajiを等重みにした。

主要条件は、全体53%以上、各phase45%以上、100クラスタ以上、95%区間の下限が50%を厳密に超えること、運用条件の通過である。128クラスタ、10000回の層別bootstrapを使用し、全条件を満たした。Mtaji単独の優越性を統計的に証明した結果ではない。

低設定のNamuaは68.75%、Mtajiは53.125%で、参考基準を通過した。低設定の結果を主要256局に加算せず、P8の512局とも合算しない。

## Workerの運用結果

起動から応答までを測定した。標準設定の7641要求では、設定時間+500ms、すなわち1000msを超える要求は両構成とも0件だった。候補の中央値264.28ms・95パーセンタイル560.65ms、基準側425.35ms・563.02msだった。各構成が実際に訪れた局面は異なるため、この比率を同一局面での純粋な推論高速化率とは解釈しない。

低設定では900ms超過が候補1/870件、基準1/863件あり、最大は候補1268.36ms、基準4000.75msだった。候補の超過率増加を5ポイント以内とする条件は通過したが、画面の応答時間を保証する結果ではない。外れ値の原因を確定する追加測定は本工程では行っていない。

正式実行は2026年9月9日、凍結コミット003b91095d93f94e03b53ea9c65a433a1f525590で一度だけ行い、3507.2033353459997秒で終了した。Node v24.19.0、Python 3.12.14、NumPy 2.3.5を使った。採用元176局面を再構成し、全352局10329手の合法性、担当側、最終状態、得点、軌跡識別子を検算した。Pythonによる独立集計も合格した。ルールエンジン自体は共通であり、独立したBaoルール実装との比較ではない。

全195ファイルのアーカイブと凍結依存74ファイルのhashを確認した。時間付き対局の再実行、モデル調整、閾値変更、局数追加、seed再利用は行っていない。

## 公開採用までの残事項

標準持ち時間と毎手Worker起動でも強化が残る根拠は得られた。スマートフォン実機、Safariなど他のブラウザ、expert設定、長時間の画面操作と端末の発熱を含む使用感は未確認である。PCの低設定をスマートフォンの実測と呼ばない。
