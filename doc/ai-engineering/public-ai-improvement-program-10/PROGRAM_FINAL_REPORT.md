# PBAI-P10：中断調査と最終判断

## 結論

正式判断は`TECHNICAL-INVALID / HOLD`。実行セッションが失われ、低設定の主要試験の途中で記録が止まった。固定した主要局数と最終検算が完了していないため、expertの棋力改善を認定しない。候補が弱いという結果ではない。expertはAI-GEN3を維持し、hardのADOPTと配信確認を変更しない。

これは監視器が生成した終了結果ではなく、凍結した中断規則に基づく事後の判断である。[判断記録](../../../artifacts/pbai-p10/incident/ADJUDICATION.json)に出自を明記した。元のrunには`FINAL_RESULT.json`がなく、その場所へ終了結果を後から作っていない。

最後の記録は開始から約25分41秒後であり、固定した12時間の上限到達ではない。正確なプロセス終了時刻は取得できていない。

## 原因の評価

元の端末セッションへの再接続は`exec-server transport disconnected`と回復タイムアウトで失敗した。現在のプロセス一覧には試験の監視器・対局プロセスがなく、環境管理プロセスと実行サーバーの起動は試験開始後だった。実行環境の再作成や切断が疑われる。

ただし、基盤側の停止理由、終了コード、OOM記録は取得できていないため、根本原因は未確定である。AIの例外、メモリ不足、対局側の10秒期限超過を原因と断定する証拠もない。

チャットに付随する実行セッションへ長時間試験を置き、その継続を前提に案内したことが運用設計上の問題だった。前回報告時点では記録の進行を確認していたが、その後の継続を保証できる基盤ではなかった。今後、実行中という案内には最終記録時刻と実行基盤を添え、セッションの残存だけを完走保証にしない。

## 証拠の保全と診断

元の生記録27ファイルをbyte単位で保存し、[アーカイブ索引](../../../artifacts/pbai-p10/incident/RAW_INDEX.json)へSHA-256を記録した。112件の固定ソースと開始時のSOURCE_LOCK hashも一致した。過去P6〜P9の記録、P10のSPEC・PROTOCOL・実行器は変更していない。

別の診断ラッパーから凍結済み検算器を実行し、出力だけを診断用ディレクトリへ分離した。元の検算器の条件は変えていない。全136 source局面と完了ペア36局1,170手を再構成した。追加のログ検算では、片側完了・途中対局も含む1,237手について合法性、担当側、seed、時間・深さ設定、候補識別子を確認し、すべて通過した。ログからは37局の完了と1局の途中状態を確認した。

この検算は`diagnosticOnly: true`である。共通ルールエンジンによる保存棋譜の整合確認であり、独立ルール実装による証明ではない。時間付き対局の再測定、未完了対局の補完、部分勝率を使った採用判断は行っていない。

## 対応と次の境界

同一試験を再起動しない。停止前の対局やsourceを、新しい最終評価に再利用しない。P10の3種類のブラウザ計27項目、既知72要求、回帰15件の成功は当時の動作確認として保持するが、正式対局の未完了を補うものではない。

[実行基盤の対策](EXECUTION_RECOVERY.md)に、GitHub Actions上の独立ジョブと成果物引継ぎの確認、および次の試験の設計条件を記録する。新しい棋力試験は別の事前契約と未使用seedが必要である。P10を成功へ変更する処理ではない。

main統合、公開切替、正式ADOPT、AI-GEN4昇格、release ID発行は実施していない。
