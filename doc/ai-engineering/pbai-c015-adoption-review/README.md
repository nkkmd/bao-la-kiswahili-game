## 公開用組込みに必要な変更

P9の検証資産をそのままpublicへコピーする方法は採らない。検証用`logic-worker.js`は受信したseedで`Math.random`を固定し、論理ゲートの指定を常に有効にする。公開ゲームからの要求には検証用seedがないため、そのまま使えば同点選択の乱数の扱いを変えてしまう。また、候補AIの差し替え口自体には対象の難易度・評価profileを限定する条件がない。

次の組込み案を公開前の確認対象とする。これは準備案であり、既定有効化の実施記録ではない。

1. 固定モデルと静的評価器を保持し、対象を既定の`bao`・`phase2`のhardに限定する。expertは別途確認してから対象に加える案を優先する。easy、normal、明示的な別profileに広げない。
2. 公開用Workerでは既存の乱数契約を保持し、検証用のseed受信処理を持ち込まない。評価器の有効化は共有設定で制御する。
3. WorkerとWorker失敗時の直接実行で同じモデル・有効化条件を使う。モデル読み込み失敗時の扱いを明示し、基準AIへ戻せる構成にする。
4. HTMLの読み込み順、Workerの依存ファイル、Service Workerの保存対象とキャッシュ更新を揃える。オンライン初回だけでなく更新後・オフラインも確認する。
5. 診断記録に使用候補を識別できる情報を残す。公開世代名やrelease IDは、正式判断と実配備の前に更新しない。
6. 公開候補の既知局面一致、合法性、Worker失敗時、思考中の新規対局・取消、難易度変更、継続操作、切戻しを確認する。
