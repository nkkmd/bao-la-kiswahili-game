## 1. Normative terminal cases supported by the frozen baseline

`guide/10-endgame.md` states that the game ends when either:

1. one player's entire front row is empty; or
2. the player to move has no legal move.

In either case, the side satisfying the losing condition loses and the opponent wins.

Front-row empty is checked during a move as well as at turn boundaries. If a capture removes the opponent's final front-row kete, the game ends immediately rather than completing the captured-seed sowing first.

These semantics agree with the runtime engine's `front-empty` and `no-move` outcomes and are accepted as exact terminal base cases for this Study, subject to canonical-state verification.

## 2. Relay termination

`guide/08-relay-sowing.md` specifies ordinary relay continuation: when the final kete lands in an occupied pit and no capture/special stop applies, the contents are lifted and sowing continues. An empty landing pit normally terminates the move.

The same guide records that R-002 contains a **computer-specific** treatment for an overlong/non-ending move, but explicitly does not adopt that treatment as a formal human competitive rule. Handling of truly non-ending relay sowing remains unresolved for ordinary play.

`RULES_BASELINE.md` independently states that the runtime relay cap exists to protect the browser implementation and is not an added normal Bao rule.

Therefore:

```text
engine reason = relay-limit
!= normative game terminal
!= automatic loss
!= draw
```

## 3. Draw / repetition

`guide/10-endgame.md` states that the reviewed baseline materials do not establish an ordinary draw condition. It specifically rejects adopting rules such as a fixed move-count draw or automatic loss for a non-ending move as the general human rule without a separately chosen competition rule/adjudication.

The runtime engine likewise has no intrinsic draw or repetition state.

Therefore this Study freezes:

```text
formal draw rule = NONE ESTABLISHED
administrative max-ply draw = NOT A GAME-THEORETIC DRAW
multi-turn unresolved fixed-point state = RECURRENT / CYCLE-REGION
```

`DRAW` remains a reserved label and is not emitted by Study 1 unless a separate normative rule is prospectively established before a future scientific freeze.

## 4. Move-level nontermination gate

The research transition adapter removes the runtime `MAX_RELAY=512` result shortcut and detects exact repeated move-internal microstates.

If a legal move in a candidate closure produces `MOVE-NONTERMINATION`, the current frozen rule baseline does not supply an authorized WIN/LOSS/DRAW value for that move. Consequently the entire candidate exact domain fails the Stage 0 exact-eligibility gate.

The Study does **not** repair this by treating the move as illegal, assigning the opponent a win, truncating it, or applying an engine evaluation.

## 5. Resignation

The human-readable baseline notes resignation as a possible practical game ending. Resignation is a player declaration rather than a deterministic board-state transition generated by `public/engine.js`. It is therefore outside the exhaustive game graph for Study 1 and is not a terminal base case.

## 6. Exact claim boundary after this audit

A frozen bounded domain can support exact forced-terminal WIN/LOSS classification only if:

- every outgoing legal move has a well-defined terminating successor under the audited ordinary transition semantics;
- `front-empty` / `no-move` terminal states are canonically reproduced;
- no runtime relay-limit result is used as terminal truth;
- unresolved multi-turn recurrent regions remain distinct from formal draws.

This audit does not claim to resolve the rules of non-ending Bao play globally.
