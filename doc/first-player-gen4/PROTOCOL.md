# AI-GEN4先攻・後攻差追加研究 — 事前計画

研究ID: `FPA-GEN4-STUDY1-20261003-v1`  
機械定義: [`protocol.json`](../../tools/research/first-player-gen4/protocol.json)  
固定ソース一覧: [`source-manifest.json`](../../tools/research/first-player-gen4/source-manifest.json)

## 1. 問いと主要評価

標準初期配置から生成する2種類の序盤分布において、同じAI-GEN4の公開expert相当を双方が使ったとき、先攻の勝点率は50%からどの程度離れるか。探索強度・評価・開局長を変えても傾向が維持されるか。

主要条件は`G4E2000`、主要領域は8手序盤の`uniform`と`top3`です。領域ごとに別々に判定し、異なる序盤分布の合算をBao一般の先攻勝率と呼びません。開始時の先攻と途中局面の現在手番を区別します。

## 2. 現行AIと対戦条件

実行時は7つの公開JSをVMに読み込み、`BaoReleaseAI`と`BaoReleaseConfig`を通します。AI-GEN4条件では`PBAI-C015-v1`と評価器フォールバックなしを各判断で確認します。

|条件|評価|通常探索の最大深度|1判断の時間条件|役割|
|---|---|---:|---|---|
|`G4D4`|AI-GEN4論理ゲート|4|深度完了を要求、10秒の安全上限|再現可能な低強度追試|
|`G4D6`|AI-GEN4論理ゲート|6|深度完了を要求、10秒の安全上限|強度感度分析|
|`G4E2000`|AI-GEN4論理ゲート|12|公開expert標準相当の2,000ms|主要条件|
|`G3D4`|従来Bao評価、軽量遷移|4|深度完了を要求、10秒の安全上限|評価器依存の感度分析|

両者は同じ条件を使います。強制された単一合法手は探索せず適用し、その件数を記録します。固定深度条件で時間上限までに指定深度を完了できなければ、その対局を未決着として保存します。通常探索の深度に加え、現行のquiescence延長は維持します。

## 3. 序盤生成と実験単位

標準初期配置から8手進めます。`uniform`は全合法variantから一様選択、`top3`は着手直後の局面をAI-GEN4の静的評価器で評価し、上位3variantから一様選択します。同点は着手の正準文字列表現順で解決します。これは探索で保証した最善3手ではなく、研究用の静的評価序盤です。

各方策に1,024スロットを新規seedで生成します。復元抽出を維持し、重複局面を除外して分布を変えません。途中で終局した序盤も含めます。対戦条件は同じ開局を共有し、各開局をSouth先攻・North先攻の両座席で評価します。正しい座席交換はplayer-indexed状態だけを交換し、ローカル穴番号と方向を保持します。

一組の座席交換対局を1スロットとします。seed、開局着手列、開局状態、全対局のhashを保存します。重複開局は独立した異なる局面とは数えません。完全な着手列と同じ開局局面の件数を別々に報告します。

## 4. 実行段階と件数

1. 技術検証: 座席交換、公開評価器経路、軽量/通常遷移、保存点の再開、改変拒否、未決着集計、shard完全性をテストします。
2. 標準初期局面診断: 4条件×2座席、8対局です。推測統計の独立標本に算入しません。
3. 予備試験: 2方策×64スロット×2座席の深度4、および各方策の先頭8スロットで深度6・expert・従来評価を追加し、352対局です。正式標本とseedを分離します。
4. 本試験: 2方策×1,024スロット×4条件×2座席、16,384対局です。
5. 開局長感度分析: 2方策×4手/12手×128スロット×深度4×2座席、1,024対局です。

総予定対局は17,768局です。正式試験には新規の固定seed名前空間を使い、予備試験の勝敗を理由に件数・条件を変更しません。予備試験で技術検証に失敗した場合は、原因を記録して正式試験を止めます。

## 5. 未決着と不確実性

最大180plyは序盤を含む総手数です。`front-empty`と`no-move`だけを確定勝敗として扱います。`relay-limit`、繰り返し局面、手数上限、固定深度未達は未決着です。自動的に引き分け0.5点へ変換しません。

先攻勝を1、後攻勝を0とします。未決着をすべて0とした下限と、すべて1とした上限を計算します。座席ペアを保ち、同一開局着手列・状態hashの反復を同じクラスタとして、頻度を保持するクラスタbootstrapを10,000回行います。これは復元抽出スロットの名目二項区間より慎重な感度的区間です。有限コーパスから全開局への無条件の保証ではありません。

主条件の2領域はBonferroniに対応する97.5%区間を領域ごとに使用します。その他は探索的95%区間です。未決着の下限側bootstrapの下側分位点と、上限側bootstrapの上側分位点で保守的区間を作ります。異なる開局系列クラスタが30未満の領域では推定を確定しません。

|判定|機械トークン|意味|
|---|---|---|
|区間が全て50%より上|`FIRST-ADVANTAGE-WITHIN-DOMAIN`|当該条件・序盤分布内の先攻方向|
|区間が全て50%より下|`SECOND-ADVANTAGE-WITHIN-DOMAIN`|当該条件・序盤分布内の後攻方向|
|区間が50%を含み、全体が47〜53%内|`WITHIN-PRACTICAL-MARGIN`|当該領域で±3ポイントの実用許容幅内|
|その他|`INCONCLUSIVE`|方向または実用的均衡を確定できない|
|異なる開局系列が30未満|`NON-ESTIMABLE-LOW-DIVERSITY`|多様性不足のため推定を確定しない|

方向差と実用許容幅内の判断を同時に満たす場合は、方向差を優先し、差の大きさを併記します。探索強度による差は同じ開局の対応差として示しますが、未決着を含む条件間比較の正式検定は行わず、完全対応例だけの探索的解析にします。初手別集計も探索的です。

## 6. 再現性・停止・資源

科学ソースのSHA-256一覧を最初の実行前にコミットします。各保存点にmanifest hash、ソースcommit、Node、run/attemptを保存します。ソースhashが異なる再開は拒否します。1手ごとに原子的に保存し、中断後はhashと通常遷移による再生を確認して未完了対局から継続します。

正式試験は64shardに分割します。固定深度familyは最大4job、expert familyも最大4jobを並列実行します。各jobは235分まで、runnerは220分で保存停止します。expertの1jobは16スロット×2座席です。明示的な取消・資源上限・基盤障害で未完了の場合、部分勝率を正式結果とせず`INCOMPLETE`として保存します。

再試行は完了対局を置換せず、未完了対局だけを保存点から継続します。時間制限expertは環境によって着手が変わり得るため、完全なbit単位の再現を保証しません。既存artifact間に同一IDの異なる完了記録があれば集計は拒否します。欠損・部分記録が1件でも残る場合、正式集計は生成しません。

## 7. 検算と報告

全開局をseedから再生成し、全棋譜を通常遷移で再生して軽量探索遷移との差を確認します。別言語Pythonで勝敗・件数・手数・未決着上下限を再集計します。これは独立したルールエンジンや区間推定の独立実装ではないことを明記します。

最終報告では初手、捕獲、reserve、NYUMBA所有、phase、到達深度、思考時間を保存した棋譜から探索的に確認します。深く解析する事後局面を正式標本へ混ぜず、必要なら別の探索的追跡として記録します。AI評価値を理論的勝敗の真値と扱いません。
