## 設計の位置付け

これは、[方式調査](README.md)で残った親runner方式を具体化する未配備の設計である。サービス設定や科学triggerとして実行できる成果物ではない。専用機械の存在、認可、十分な保存容量、runnerバイナリの一致を仮定せず、実環境の条件を確認するまで実OS成立を認定しない。

単なるjob開始hookではActions初回取得を覆えないため、**初回jobを受け取るrunnerプロセスの起動前**に親の制限と時計を確立する。hookは工程記録の補助には使えても、制限開始点の代用にはしない。

## 親監督に求める順序

1. 信頼する基盤、事前配置したruntime・runner、親監督プログラム、今回初回取得する科学inputを区別し、全pathとhashを列挙する。基盤側を新たに対象外へ移すことは契約変更なので、無言で採用しない。
2. kernelが強制する親memory上限1 GiB・swap無効と全書込先の有限領域を設定する。親監督自身も同じ予算に含める。上限未設定時や委任先が不明な場合はrunnerを起動しない。
3. runnerを起動する前に単調時計を開始する。起動、job待ち時間、Actions取得、checkout、Node準備、科学worker、圧縮、転送、artifact保全、全子停止を同じ20分へ含める。終了予約180秒に入ったら新しいworkを認めず、期限後の回収を完成へ昇格しない。
4. 対象jobを一度だけ受け取る構成を、使用するrunner版の実動作で検証する。想定外job、別head、attempt 2以降、再接続で同一科学処理が起動する経路を拒否する。登録・再登録・起動の認証情報は証拠に保存しない。
5. runnerの初期化と全childを親scopeへ継承させる。daemon経由のcontainerや別serviceなど、親scope外で動く処理を使うなら、その実行主体も管理する。子だけを移して親controllerを計数から外さない。タスクに制限解除権限を与えない。
6. 保存は原imageと封印後制御記録をhashで結合し、最後の保存先receiptの対象と終端を固定する。全child停止と保存対象の照合が済むまで完成を宣言しない。最終ACKをそれ以前に封印したimageへ含める循環条件は作らない。

## 実装前に確定する入力と出力

| 分類 | 固定・確認する内容 |
| --- | --- |
| 実行環境 | 専用host、OS/kernel、委任済み親cgroup、強制停止主体、初回起動前の制限設定経路 |
| runner | 配布バイナリのhashと公式版、ソース対応の限界、登録・受信・単一job終了の方式 |
| 書込領域 | workspace、Actions取得先、tool cache、runner診断log、tmp、圧縮出力、sidecar、転送時の複製 |
| 保存予算 | ローカル物理量とremote保存byteの合算、最大256 MiB、終了容量予約16 MiB、途中peakと最終書込後の計数 |
| 取得方針 | runner内部retryを含む取得経路、初回の失敗停止、科学lease取得以前と以後の境界 |
| 認証 | runnerの基盤認証と研究保存用認証の注入・破棄方法。値をlogやmanifestへ出さない |
| 観測 | 親scope識別、開始時刻、全phase、kernel peak、容量、最初の停止理由、全子停止と保存receipt |

runnerを含む全code・依存物・初回取得と書込領域が現在の256 MiB内に収まるとは未確認である。事前配置を使う場合も、既存契約の全input・全保存の範囲を再確認してから固定する。runner配置済みという理由で科学inputの取得費用を消したり、巨大なcacheを計数から外したりしない。収まらなければ成立不足とし、上限を拡大しない。

## 実環境を確保した後の検証

最初は科学モジュール・科学seed・旧rootを読まない専用の既知データだけを使う。検証は親環境が具体化してから一つの結合試験として設計し、既存の成功取引を再利用して実行するものではない。

確認対象は、初回取得以前の制限・時計、取得失敗時の再試行拒否、終了予約での停止、親memory超過、書込容量超過、保存応答欠落、uploaderまたは子停止失敗である。各故障で最初の理由と保存prefixを残し、未ACK・未知・未完成を保持する。単一phaseだけの合格を積み重ねて全工程成立と推定せず、原証拠から独立検算する。

## 現在の停止点とその後

現在の阻害要因は、専用親環境と初回起動経路が未確認なことである。現作業環境のcgroupは読取専用で、同環境で配備や成立試験を進めることはできない。runner登録や機械への変更を行わず、本設計をレビュー可能な状態で保存する。
