# 新しい供給方策と対象構造

## 状態と主課題

[機械定義案](DESIGN_PROPOSAL.json)はPROPOSAL-NOT-EXECUTION-REGISTRATIONで、seed区画、科学Study ID、ソース固定コミットを割り当てていない。ユーザーの継続指示に沿う設計作業である。正式な関係検証・新規source実行をこのJSONで開始しない。

主要指標は厳密な勝敗価値損失で、DTFへ差し替えない。[前段の設計案](../readiness-review-20261012/DESIGN_PROPOSAL.md)のdepth1/4比較・順位関係Z・損失Yは将来の正式登録候補として保持する。今回Z/Yは測定していない。

## 選定の機構

現行ルールのmtajiでは捕獲可能なら捕獲手が優先され、捕獲手がなければtakataの合法手集合へ進む。根拠は固定[runtime engine](../../../tools/research/g5-01/transition/runtime-engine.cjs)のlegalMovesMtajiである。rootの異なる手がこの二つの応手集合へ分岐すれば、相手の捕獲可能性を変える意思決定を含む。これは勝敗価値差を期待する機構の仮説であり、値の差を保証しない。捕獲の存在は将来の勝利と同義ではない。

短期終局層のような「全ての枝が4手以内に終わる」という採用条件を設けない。全ての直後の子を非終局とし、応手集合の種別差を条件とする。非終局真偽値以外のwinner名、終局勝者、厳密解、DTF、評価値、探索順位を選定器へ渡さない。勝敗価値の代理測定としてこの構造を扱わない。

| 項目 | 具体的な案 |
| --- | --- |
| ルール・開始点 | BAO-RULES-V0.2.0-TAKASIA-001、64種子の標準初期状態 |
| 着手方策 | canonical moveKey順、既存xorshift32・整数棄却方式の擬似乱数着手を保持 |
| 軌跡 | 各sourceを自然終局または512 plyまで生成し、最初の適格rootでは止めない |
| root | 非終局mtaji、reserve双方0、合法手幅2〜4 |
| 全root子 | 独立遷移が一致した非終局子。各応手幅1〜8 |
| 種別差 | 全合法root手の子に、捕獲手のみの応手集合とtakataのみの応手集合が両方存在 |
| 1 sourceの代表 | 全軌跡の最後の構造適格root。終局勝者や解を見ず、閉包解析前に固定 |
| 解析対象 | source順の最初の8代表まで。全64 sourceの生成・代表固定後に閉包へ進む |
| 重複・失敗 | 選んだrootやscreen子が旧既読または既選定rootに重なる場合は不採用。前の適格rootへ戻らない |

「最後」は低い閉包費用を期待して対局の後方を優先する設計選択である。小領域を保証せず、自然終局で打ち切ることも対象分布の一部である。根の探索幅や応手幅だけで将来の全分岐数を制限しない。構造適格判定を満たしたrootを選んだ後の重複・閉包失敗・価値差不足で、別rootに入れ替えない。

## 独立検算と資源

次の実装ではruntimeと独立環状配列エンジンで全root手・全応手集合を照合し、全軌跡と「それより後に適格rootがない」ことを独立に再生する。runtime guard、MOVE-RECURRENT、ADMIN-CUTOFF、遷移不一致がsourceやscreenにあればそのsourceは候補なしで終了する。候補固定後は全合法手のBFS閉包と二つの独立solverを用いる。探索深さ制限の葉を厳密解にしない。再帰未解決・部分閉包をDRAW、0損失、適格exactとして埋めない。

資源案は64 source、8候補、1領域5000状態・64000辺・60秒、全体300秒、1遷移8192 microstates、RSS 1GiB、生JSON 128MiBである。G5-02の状態上限を増やして旧候補を救済する案ではない。新しい対象でも同じ状態上限に達する可能性が残る。保存サイズを事後の圧縮成功だけに頼らず、生成時のcheckpointとサイズ監視を実装する。

旧58532 RAW識別と技術既読を遮断し、全新規trace・screen・閉包・未採用stop witnessも既読集合に残す。標準初期状態などsource軌跡自体の旧状態共有は全候補の除外理由ではないが、root・screen子・閉包全域は遮断対象である。新しい科学区画は一度だけ消費し、fixture CI合格・ソース固定後に別trigger、seed読取前の永続lease、attempt 1、常時保存を要求する。retry、上限引上げ、候補置換、件数不足の追加sourceを認めない。

## samplingと終了

当面は固定開発コーパスの全数記述を対象とし、IIDや一般Bao局面の無作為標本を仮定しない。擬似乱数着手、連番seed、別source、状態非共有だけを独立性の根拠にしない。最後の適格rootを採る規則も、全適格rootの一様抽出とは異なる。前段の「93ずつ」という条件付き精度案・信頼区間はこの開発供給へ適用しない。

報告はsource数、構造適格数、候補数、閉包成否、未知の原因、保存量、時間・RSS、共有成分、全候補の厳密価値差の有無を記述する。情報不足や資源不足でも固定区画で終了する。価値差のある候補だけを数え直さない。完全領域が得られても開発証拠を正式holdoutへ昇格させず、正式関係は別の新規登録を要する。
