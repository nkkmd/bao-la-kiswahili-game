# P/M/R改訂契約の具体案と採用判断

## 結論と現在の状態

本書はPR #234の案Bを具体化した**未採用の比較資料**である。契約、科学SPEC、認可、実装、workflowを有効化しない。科学上の上限を保ち、準備・保全・信頼基盤の費用を別に示す案を推奨する。ただし、旧契約と同等の資源条件ではない。採用判断は[判断表](#採用前に判断する変更)に分け、技術的に成立したとは扱わない。

照合基点はmain `1205afe0a2c79c957f5d21bee6b7de47a6665ae4`、tree `f6065400f243631e958f04c46214d4849b520a65`。PR #235のルールガイド更新を保持する。開始時に未統合PRと追跡済み差分はなく、未追跡一時ファイル2件は対象外とした。ChatGPT側の作業領域はユーザーのWSLではない。

G5-01〜05の320 sourceと16完全領域は過去の成果として保持する。主要準備判断は`PRIMARY-READINESS-NOT-MET`、BEFCSと正式関係は未登録・未実行である。BEFCSの科学seed消費0・leaseなし、`wholeLifecycleOsProven=false`、既存の実装移行停止を維持する。

## 段階・担当・時計

信頼基盤Kは、OS/kernel、OS manager、Actions基盤またはWSL管理基盤、実行を制御する監督S、認証・固定保存先である。Kを無資源とは扱わない。科学workerには上限変更、manager操作、直接外部通信、科学用認証情報を渡さない。Sは科学モジュールをimportせず、固定入口を一度だけ起動する。新しい監督設定・codeの配置と検査はPへ計上し、S自身の稼働費用は制御台帳Cへ継続計上する。

| 段階 | 開始と終了 | 含める処理・禁止する移動 |
| --- | --- | --- |
| P: 準備 | Sが今回の準備を受理したtPから、全入力のバイト照合・制限準備が終わるt0まで | runtime・固定code・固定入力の取得、hash/size/実行bit照合、専用書込領域・通信役割の準備。科学codeのimport、保護集合の展開/解析、科学seed読取・生成、lease/consumeは禁止 |
| M: 科学処理 | OS制限と単調時計を確立したt0から、科学子孫の停止を確認したtMまで。最初の科学exec/importより前にt0を記録 | 科学codeの初回ロード、入力の展開・遮断集合構築、lease/consume、生成・選定・全閉包・独立検算・科学journal。時刻超過後に完了記録を成功へ更新しない |
| R: 保全 | 最初のmirror準備時tRから、固定保存と最終制御取引を閉じるtRendまで | M中のmirror、停止後の封印・圧縮・転送・receipt照合。既存byteのhash/size/順序照合だけを許す。遷移再生・解法・選定再計算はM内で終える |
| C: 制御 | tPからtRendまで | Sの時計・監督・停止・資源計測・限定通信制御。M中のSをP終了で無料扱いにしない。Cは第四の科学工程ではなく全段階を支える費用項目 |

PからMへの移行時に、入力manifest、利用runtime、Kの構成識別、制限値、許可操作表を固定する。Pで置いたruntimeは読取専用とし、科学codeと科学用固定入力はMの容量対象へ一度配置する。科学codeのPでのバイト照合は許すが、実行・事前import・科学的cache作成は許さない。Pの残存daemonはC/Rへ帰属を移すか停止する。未分類のprocess・書込先・通信があればMを開始しない。

固定入力の最終リスト・byte数と、上記の配置が256 MiBへ収まることは未確認である。runtimeや読取専用ライブラリをMの保存上限から外すことも旧全入力計数からの変更であり、Pの残存容量とMのmemoryには計上する。runtime cacheやtmpをこの例外へ含めない。

M中のtask同時memory上限はM1024 + R512 + C128 = 1664 MiBで、P中はP2048 + C128 = 2176 MiBとなる。両段階を跨ぐtask親上限は2176 MiB・swap 0とする案である。P残存物の稼働はこの内数に入れる。OS・標準runner等のK全体がこの上限に入ったとは主張しない。

Kについて、実行環境の割当memory/disk、image/runtime識別、job時間、保存期間、課金単位・見積上限を別欄に示す。共有OSの実使用量や初回基盤準備費を測れなければ`null`と理由を記録する。これはtask予算と基盤割当の二層保証であり、host全体の実測合算ではない。K込みの有限割当を説明できない環境は採用不可で、料金不明を0円とはしない。

費用はCPU時間、段階wall time、重複区間、task親peak、K割当、local/remote peak、累積送受信body、protocol overhead、remote byte×保持期間を別々に報告する。共有fileは物理identityで一度、コピーは各々計数する。段階別には両方に現れ得るため合計には重複控除表を付ける。Kの既設cacheも存在量と今回利用範囲を明示する。

## 数値維持でも変わる科学的条件

従来は初回準備と保存にも20分を使ったが、本案では科学Mに最大20分を使える。runtimeや圧縮コピーを科学保存256 MiBの外へ置くため、従来候補より科学証拠へ割ける量が増える。外側memoryも増える。同じseedや選定規則でも、時間打切り・OOM・保存停止で残る候補や検算済み領域が変わり得る。旧runとの等資源比較や同じ成功率は主張できない。

新案ではM内の初回import、科学input解釈、独立検算、科学保存と待機時間を差し引かない。mirror待ち・consume待ちもM時計を止めない。Rへ科学処理を逃がさず、M停止時に解釈未完だった解をRで完成扱いにしない。Rの保全改善は欠落を減らし得るが供給能力の科学的改善とは別である。変更は未実行BEFCSの新しい事前条件としてのみ検討し、旧320 sourceや旧全工程判断へ遡及しない。

## 操作別の通信案

ここでいう要求はapplication層の論理操作であり、TCP再送の不存在を意味しない。DNS・TLS・redirect・Git/SDK内部再試行は経路台帳へ列挙する。科学的な意味を持つ書込は最下位の実操作まで一回へ束縛する。汎用runnerを改変する前に、科学操作だけを限定brokerへ分離できるかを確認する。

| 操作 | 時点・回数案 | 失敗・応答不明の扱い |
| --- | --- | --- |
| 固定環境/code/inputの取得 | Pのみ。固定hash/size/URLへ最大3試行、全体256要求/600秒/1 GiB内 | 科学操作開始前に限定。hash不一致・対象変更は即停止。後から科学inputを追加取得しない |
| 全区画lease | M内で原子的CASを1回 | 固定run/head/attemptと全区画を結合。成功ACKと対象照合がなければconsume禁止。再発行・新ownerでの救済禁止 |
| durable consume | 最大128論理markerを各1回、PRNG初期化前 | 所有lease、seed index、run identityを結合。成功確認前に初期化しない。応答不明で全ての新規読取を閉じる |
| 科学実行 | 固定入口をattempt 1で1回 | 同じlease/区画の再起動・resumeなし。workflow再実行も拒否 |
| M中のmirror | 64 KiB以下の固定prefix片、最大4096書込、累積保存256 MiB内 | sequence/hash/直前receiptを結合し、各書込1回。次片は前片の確認後。最初の失敗で新規科学読取を停止 |
| Dの最終保存 | gzip最大6片＋manifest取引1回。各片・取引は一回 | 既存成功片を再送しない。曖昧な保存を上書き・forceで成功化しない。異なる科学結果の再生成禁止 |
| 保存receipt用読取 | 各書込に対し事前に固定したmetadata照合＋内容読戻し各最大1回 | 読戻し失敗はACK不成立。M/R/C合計body 1 GiBと時計内。失敗後の新規確認要求で救済しない |
| Tの終端保存 | 固定control envelopeを一回 | 終端receiptで閉じる。ACKをTへ入れ直す再送をしない |
| 実行後の独立読取 | 別の監査記録・対象hash・有限予算を定めた読取のみ | 実行内ACKへ昇格させない。新規科学生成・未知の解消はしない。今回は新取引を実行しない |

最終Tには確認用の追加要求を出さない。lease/consumeの確認用読取も書込ごとに上表の2回以内とする。事前registry照合はM内で1回。M/Rの最大論理書込数は1 + 128 + 4096 + 6 + 1 + 1 = 4233、確認用読取は最大8466（Tにも2回を見込んだ保守的な上限）、事前照合1回を加えた合計12700要求を上限案とする。各要求10秒以内で、段階・総時間上限が優先する。これは全要求を実行できる予算ではなく、到達前にも時間・byteで止まる上限である。Gitで一論理操作が複数要求へ分解される場合も、実要求数をこの上限へ計上する。

科学通信の最初の失敗・応答不明後は、科学側への新しい許可を不可逆に閉じ、進行中の科学処理も共通停止へ移す。残るRは、既にある証拠prefixと最初の失敗を、**事前に別枠で固定した停止保存先**へ一回保全するだけとする。曖昧な取引の確認や再発行はしない。正常保存と停止保存は同じ予約slotを排他的に使い、既に試行したslotを停止保存名義で再使用しない。この停止保存例外も従来の一律停止からの変更で、現在は未認可である。上表のmirror/保存数とbyte上限に停止保存を含め、別枠を追加容量にしない。

標準Actionsの基盤heartbeat・job受信・log送信はKであり、科学leaseや科学データを運ばせない。K通信へ全ての無再送要求を課さない変更を提案する。ただしKの再接続が科学入口を再起動できないこと、科学token・seed・可変入力がKのcacheやlogへ漏れないことを確認する。内部通信を制限できないという理由で科学brokerの重複要求を許さない。

## 保存対象と有限な終端

固定保存対象はファイル名だけでなく、role・相対path・size上限・sequence・hash・保存先・成功条件を最終manifestへ列挙する。現在は役割を定めた案であり、最終path/hashは未固定である。

| 記号 | 対象・上限案 | 作成者と保全先 |
| --- | --- | --- |
| D | Mの科学原証拠・consume/候補/journal・全辺/microstate/metadata・未展開境界・独立検算結果・停止prefix・入力manifest。expanded 256 MiB内 | Mが書き、全科学子孫停止後にRが読取専用化。原image方式なら未使用領域も含む原image全体を対象にする。Rでgzip化して最大6片・合計256 MiB内を固定remoteへ保存 |
| A | D保存の実行内ACK。取引ID、期待/実ref、commit、manifest/hash、読戻し一致、観測時刻 | Rが受領しCへ記録。D自身に入る必要はない。Dの存在だけから生成しない |
| T | D識別、Aまたは未ACK、最初の停止理由、各段階・総費用、部分prefixの解釈、停止証拠E、欠落一覧。最大4 MiB、Cの16 MiB内 | Sが一回だけ封印し固定control保存先へ送信。未取得の最後のACKを先取りして含めない |
| E | M子孫とR補助子孫の空化、終了code/理由、cgroup identity、開始終了時刻、制限・peak・OOM状態 | OS側の観測をSがTへ結合。M/R本人の自己申告だけでは不可。確認不能ならTに未確認を記録 |
| U | Tを受理した固定保存先の終端receipt。T digest・run identity・受理時刻・対象保存の結果。最大1 MiB | 保存サービス側で有限に確定する最後の記録。responseをSが実行内に受領・照合して成功扱いにする。U自身のACKを再び保存する条件は課さない |

Tの資源欄は封印直前までの実測と、最後の送信・U受領に予約した上限を分ける。T自身の送信後の費用をT内の実測として先取りしない。最終bodyはT最大4 MiB＋U最大1 MiB、Cのmemory 128 MiB、段階締切の残時間を上限として確保し、足りなければ送信前に未完とする。Uが返す受理時刻・sizeは保存側の観測で、送信側の最終peakではない。Kの後続logから得た実測は事後監査として別に示し、不明な残費用は上限以下・実測不明と報告する。

順序は、Mの新規読取停止→M子孫停止確認→D封印→D保存/照合とA→R補助子孫停止確認→T封印→S自身による最終送信→U受領/照合→終了である。T送信のために新しい子を起動しない案とする。既知の停止理由が発生してもTには失敗を残し、成功へ書き換えない。

**この終端案は、S自身・OS manager・保存サービス自身の終了までをEへ含めない。** SをKの一部として信頼し、科学実行権限を既に閉じ、M/R補助子孫が停止した後の一回送信だけを任せる。S自身の最後の終了とU受領の外部証明は、基盤logによる別の来歴とし、後から回収できても実行内ACKへ置換しない。従来の親終了まで含む保証を狭める実質変更であり、受容しない場合はこの案を採用できない。

代替案は、Sの終了を独立OS managerが観測し、専用の受信側へEを確定させる方式である。追加主体・保存量・時計・最終receiptを予算内へ具体的に対応付ける必要があり、既存資料では成立していない。循環があるから不可能とはせず、無期限の追加基盤開発も前提にしない。

U未受領・保存応答不明・E不明・期限超過・制御量超過では、実行内保全完了を宣言しない。後日D/Tが見つかっても未ACK状態を保持する。Dの科学検算合格と、A/T/E/Uの運用完了を別fieldにする。全体未完から供給0件や仮説否定を導かない。

固定remoteのdurability、原子的受理、receiptの改変拒否、受理後の読取方法と保持期間は依然として採用前gateである。Uは現行APIが提供済みの機能名ではない。既存Git receipt/Actions artifactの何で代替できるかを最小実装表で照合し、一致しなければ保存候補を不合格とする。

## ActionsとWSLを同じ条件で比べる

Actionsは標準GitHub-hosted Linux VMを第一比較候補とする。WSLは代替候補で、self-hosted/custom runnerを必須にしない。比較は本書の同じB1・科学入口・保存終端・信頼境界を用いる。実証済みの部品と今後の必要作業を分ける。

| 条件 | GitHub Actions | ユーザーWSL |
| --- | --- | --- |
| Kと準備の境界 | VM・標準runnerをKとし、今回の取得/設定をPへ。初回runner準備をM外に置く変更が必要 | kernel/systemd・既設runtimeをKとし、今回の配置/設定をPへ。同じ境界変更が必要 |
| 制限と権限 | 保存済みcgroup/有限image部品あり。固定OS image、専用UID、task上限・egress・停止は新契約では未結合 | 共有観察はsystemd稼働/委任等のみ。上限変更拒否・FD・kill・隔離の実効性は未検証 |
| runtime/code | 科学runtimeを固定し、初回importはM。runner内Node20との共用を要求しない | 同じruntimeを固定。インストール済みであることから互換性を推定しない |
| 一度限り性 | run/head/workflow/attemptをbrokerで結合し、手動rerun・基盤再接続でも二度目の入口を拒否する必要 | 専用run identityと永続leaseで同じ拒否が必要。端末再接続・再起動でresumeしない |
| 保存終端 | 既存capsuleのD/Aは部品証拠。T/E/Uと停止後600秒・容量は未成立 | 同じD/A/T/E/Uが必要。WSL shutdownや端末終了を正常保存としない |
| 操作・後片付け | job VMの廃棄を利用可能だが、M/R停止証拠の代用にしない | 専用領域・資格・残存物の撤去計画が必要。現user serviceを直接変更しない |
| 外部費用・保持 | KのVM割当、利用分数、artifact/remoteのbyte×期間を記録。実際の権限・課金設定は未確認 | host/VM割当と電源/通信・local/remote保持を別記録。無料とはみなさない |
| 現在の比較判断 | 第一候補。利用可能性と本契約成立は未認定 | 代替候補。観察の反復は次の作業にしない |

資料確認日2026-11-05。GitHub公式の[VMとjobの説明](https://docs.github.com/en/actions/how-tos/manage-runners/github-hosted-runners/use-github-hosted-runners)、[管理権限・通信の説明](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)、[保存期間の説明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository)を参照した。Linux VMのsudo提供は今回の隔離成功を証明しない。Actions artifactは期限付き保全であり永続正本の代用にしない。WSLは[共有観察と出所](../runner-topology-20261017/host-observed-20261105/README.md)だけを根拠とし、現在値・管理権限・全祖先のmemory/swap制限を推測しない。
